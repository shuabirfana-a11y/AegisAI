# 情报总览 UX

任务：JTBD-01/11/13。R1先知道“发生什么、为何关注”；R2同时知道“数据还更新吗”。30秒是待实测目标。首屏先范围与变化，再值得关注列表和来源摘要；不设计数字大屏。

## 信息层级及操作

1. [D01] 时间窗（默认最近24小时系统观察）、as_of、覆盖产品/生态、来源启用范围；切时间/产品并主动刷新。独立支持按源发布日期的视图，不能把历史首次导入叫最新发布。
2. [D02] 新发现、已更新、知识更新三个入口，点击打开同快照集合。新发现=窗口内首次系统观察的去重实体；已更新=窗口内事实revision有变化的已有实体；新增与更新不相加成独立主体。知识按论文/标准/政策等类型细分，标准实施日不当发布日期。后台任务重复抓取不增加计数。
3. [D03] “值得关注”少量条目：当前产品+具备有出处的CVSS评分/PoC关联/KEV收录/风险事实更新等信号；每条显示为什么进入、时间及未知，点击详情。默认先显示新KEV收录，再已关联PoC，再显式评分严重度，同组按最新业务变化；无数据的因子不补零或乘成总分。CVSS需版本/来源，跨版本并列不混排为一个分数。
4. [D04] 近期情报列表按去重实体变化展示title/type/product、变化摘要、原发布日期/本次观察日期，漏洞与知识详情分流；时间线只呈现有Evidence的事件，PoC发现日不冒充代码发布时间。
5. [D05] 启用源最后成功及stale/failed摘要，点异常进入该source失败run。17个计划入口不能显示“17源实时在线”，类别和入口数分别列。
6. [D06/D07] P1具备后才开放资产影响与待复核数，分别链接授权匹配集合/问题集合。无资产未配置说明而非零风险，复核未实现不显示假待办计数。

“高风险”入口实际带明示CVSS version/severity筛选；“PoC”区分已关联与可用性；“KEV未收录”只指某次完整目录。无正式后端时设计稿用[真实数量]/[as_of]占位，不能展示99%安全。

## 状态与恢复

Loading保留窗口和之前内容，统计不可显示0；Empty显示尚无运行情报/未完成基线及来源配置；No Result说明当前窗口未匹配并提供扩大时间；Partial Data逐模块标缺失源并保留可用结果；Stale Data显示每源最后成功和数据日期，不盖掉旧证据；Source Offline点到失败任务。Conflict只提示具体字段/待复核对象[P1]；Evidence Insufficient显示为何列入候选。Error带request ID和重试，不能清掉用户窗口。Agent Timeout在本页不适用（没有Agent任务）。Permission仅作用于资产/待复核/运维动作，不影响公共概览。

## 成功与数据约束

任意卡片的计数能进入同条件列表；任意关注项能打开真实风险Evidence；异常能定位真实run。BACKEND REQUIRED：D01—D07见依赖矩阵，sourcechecked_at与研究样本不能替代本页运行数据。首批三源只M0，M1知识、厂商、PoC及问答来源补齐后才能形成完整总览。
