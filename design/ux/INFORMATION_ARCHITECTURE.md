# AegisAI Phase 3：信息架构冻结

2026-10-03。仅设计：下列页面、按钮和数据能力尚未开发。本阶段以冻结需求、已选数据源和赛题4页原文为输入，不生成正式UI或服务。

## 【最终一级导航】

情报总览 → 情报中心 → 资产风险 → 待复核 → 智能问答 → 系统运行。

六项是完整产品的导航结构。资产风险、待复核属于P1，运行时只展示已经实现且允许访问的入口；未实现模块不能通过空卡片伪装为已接入。智能问答属于M1/P0，不能移到可选版本。默认打开总览。

## 【7个核心页面及目的】

| 页面 | 目的 | 范围 |
|---|---|---|
| 情报总览 | 30秒内看新增/变化、值得关注项和更新可靠性 | P0；资产/复核摘要P1 |
| 情报中心（含漏洞视图） | 以产品、风险和状态找目标；按类型浏览知识 | P0；资产筛选P1 |
| 漏洞详情 | 回答是什么、影响谁、风险、处置、证据和变化 | P0；Patch/冲突/资产P1 |
| 资产风险 | 最小组件登记、三态影响、处置优先理由 | P1 |
| 待复核 | 同范围事实对照、人工结论与审计 | P1 |
| 智能问答 | 调用真实只读工具调查，结论能回到证据 | P0；资产/复杂多轮增强P1 |
| 系统运行 | 查看真实同步状态，定位和恢复失败任务 | P0；高级运维按后续需求 |

“漏洞中心”是情报中心的默认漏洞视图，文件名保留用户指定的VULNERABILITY_CENTER_UX.md。不能因为菜单名称丢掉赛题明确要求的论文、标准和政策。

## 【5条核心用户流程】

FLOW-01 新漏洞→详情→Evidence→风险判断。
FLOW-02 同范围冲突→证据对照→待复核→人工决定→详情。
FLOW-03 资产命中→详情→PoC/修复→有出处的处置建议。
FLOW-04 复杂问题→实际Agent任务→结果列表→详情→Evidence。
FLOW-05 总览来源异常→系统运行→失败SyncRun。

正常、异常、权限及返回路径见CORE_FLOWS.md。步骤预算是待实测目标，不是已验证的用户测试结果。

## 【比赛Demo主路径】

围绕同一组件风险：总览→漏洞详情（证据、复核、资产摘要在原上下文展开）→智能问答→点击结果回详情。M2真实资产/复核就绪时展示完整4分钟故事；M1路径删去尚未实现的P1操作并明确标识，不能称已覆盖资产和人工复核。故障流程单独作为现场备选，不打断主故事。详见DEMO_FLOW.md。

## 【后端必须提供的数据能力】

BACKEND REQUIRED：类型化情报与稳定身份；生态包/版本确定性判断；字段Claim/Evidence/raw版本与lineage；明确fixed及厂商建议；PoC关联和独立可用性状态；源日期化CVSS/EPSS/KEV；关联论文/分析/标准/政策；一致快照统计/搜索/分页；可审计只读问答任务及引用；真实Source/SyncRun/失败恢复。P1另需资产匹配、同scope冲突、Review并发写入/审计、Patch关联。详细元素和API提案在PAGE_DATA_DEPENDENCIES.md，全部尚未实现。

## IA层级与页面理由

```text
AegisAI
├─ 情报总览：默认入口；新增、关注、来源异常
├─ 情报中心：同一搜索与类型过滤框架
│  ├─ 漏洞：默认视图 → 漏洞详情（第7个核心页）
│  ├─ AI事件 / 分析文章：无CVE事件与技术研究
│  ├─ 论文：arXiv ID与版本
│  ├─ 标准/规范：正式标准与指导框架分组
│  └─ 政策：正式文本、发布机关与显式日期
│     └─ 共享知识详情（辅助模式，不新增一级导航）
├─ 资产风险[P1]：组件列表 → 组件影响展开 → 漏洞详情
├─ 待复核[P1]：问题队列 → 单个复核任务/审计 → 原Claim
├─ 智能问答：调查工作区 → 任务/结果 → 漏洞或知识详情
└─ 系统运行：来源列表 → 同步历史 → SyncRun详情
所有Claim → 共用Evidence抽屉/深链接；保持原页面上下文
```

资产影响、Review任务、SyncRun和知识详情是各核心页的子视图，不复制一套首页/搜索/聊天页面。登录能力已有时读取会话权限；本轮不规划企业IAM页面。权限是执行边界，用户职业不自动获得复核/重试权限。

## 三个身份删减与验收

| 视角 | 初稿中容易产生的负担 | 最终删减/合并 | 保留理由 |
|---|---|---|---|
| 安全分析人员 | 首页多图表、详情每次另开Evidence页 | 删除装饰图表；证据共用抽屉，风险逐项解释 | 更快判断且不丢原字段 |
| 开发人员 | 7个一级菜单、每页一个聊天组件、源能力默认可用 | 详情降为子页；仅一个问答工作区；逐元素BACKEND REQUIRED | 单一数据契约，避免空能力 |
| 比赛评委 | “智能指数”、虚假冲突、所有状态绿色 | 删除未知指数；真实同scope对照；PLANNED/失败真实展示 | 每个结论与运行证明可核验 |
| 三者共同 | CMDB/全网扫描/知识图谱/实时攻击执行入口 | 不设计入口；SBOM和复杂运维延期 | 不扩大P0，不增加无证据或危险操作 |

验收逐JTBD/流程检查及修改记录在USER_JOURNEYS.md；文件/ID/数据依赖/返回路径完整性核验在validation.json。设计检查不等同后续可用性实测或功能验收。
