# Evidence交互与事实核验

目标：用户看到任何可行动的结论，都能查看“谁在什么范围、什么时间说了什么”。Evidence不是引用链接清单，Claim也不是LLM自信分。

## 共用抽屉和直接访问

任意字段的“查看证据”打开同一个抽屉[E01/E02]，保留原页面和Claim锚点。抽屉顶部显示字段/value、scope、Claim revision及四态；下方来源对照。关闭返回原字段[G03]；直接打开Evidence深链接[E03]时显示对象/Claim面包屑，允许回详情，不出现无来源孤立页面。

| 用户区域 | 必须看到的数据 |
|---|---|
| 结论 | Claim值、生态包/版本或分支/日期/CVSS版本scope，人工决策与上游观察区分 |
| 来源 | Source ID/名称、实际publisher/provider、官方原URL；镜像平台另标 |
| 原文 | 原文片段/语言，必要摘要标derived，引用不被摘要替代 |
| 时间 | published/modified（源未知不代填）、retrieved、Claim核验时间，明确各自含义 |
| 核验 | 四态、support/refute/context关系、规则/人工依据、操作者和适用范围 |
| 定位展开 | raw ID/revision/hash，解析后的JSON Pointer、PDF页码或文本span；只访问已获授权原始记录 |
| 来源关系 | lineage：原发布者→转载/聚合/镜像链；同源重复不增加独立票 |

版权/访问限制时只显示允许片段和正式原文链接，不承诺标准/论文全文都可下载。URL打开外站前说明“原始发布站点”；不存在跳转到未知PoC执行、代理抓取任意URL或下载按钮。

## 多来源与真正冲突

先比较对象、生态、包名、版本/分支、发布时间/评估时间、评分版本和字段定义。一致转载归一组；不同scope并列“上下文不同”；同scope明确矛盾显示“存在冲突”，保留两值、两Evidence和对应Review[E04]。缺少范围只能“证据不足”，不能凭数值差异确认冲突。

**假设交互例（不是实际漏洞或gold）**：相同包/生态、同一版本分支和评估口径，Source A明确受影响<0.8.4，Source B明确<=0.8.5。抽屉列出两条完整Evidence与时间，说明差异涉及0.8.4—0.8.5，提供进入P1复核。真实演示必须另外验证这些条件。

反例：CVE-2025-32434的CNA CVSS4.0=9.3和NVD CVSS3.1=9.8是不同版本，不能用来演示同scope冲突；NVD本期独立采集暂缓。OSV/GHSA/CVE转录同一公告不是三份独立确认。

## 状态与人工更新

未取原文但存在引用：待确认，写“只有引用线索”；原文不足：证据不足及原因；加载失败：保留Claim和其他Evidence、单项重试；源离线：可读已存快照及日期；原始全文受限：给允许摘要及官方链接；无权：解释受限，不能显示私有资产片段。原文/历史Evidence缺失时不说“已确认”。

P1人工操作跳对应Review而非在证据抽屉提供第二套写入表单。提交权限、revision、理由及审计只在Review契约执行；返回后刷新该Claim及其时间线。源的新修订产生新Observation/Claim候选，不自动覆盖既有人工结论。引用绑定raw revision/hash；新旧对比必须可回看旧证据。

## 验收与依赖

1. 版本、评分、PoC、fixed、资产影响、问答各选一结论，均能显示对应Claim和locator。
2. 关闭/直接深链接都能恢复调查，且旧revision引用不漂移。
3. 镜像并组、跨CVSS版本并列、同scope真矛盾分开处理。
4. 不把四态汇总成整条漏洞的无条件“可信”；不把授权核验以外的PoC相关认证为可用。

BACKEND REQUIRED：E01—E04和K01，Evidence Store/lineage/定位/审计均尚未开发。实现需保持Phase 2 null/[]及未知reason契约。
