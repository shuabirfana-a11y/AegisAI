# 待复核中心 UX（P1）

任务：JTBD-08/09。这里处理“具体对象的具体问题”，不是普通待办；权限不因为安全分析人员身份自动授予。P0只读字段未知/证据依然必须展示，P1Review写入未就绪时不提供假提交入口。

## 触发与优先顺序[R01]

实际同scope来源冲突、PoC关联依据不足、版本歧义、Patch关联不确定、关键授权资产受影响但结论缺证、证据不足。重要资产“affected”本身不是冲突；只在需要人工判断或依据不足时触发任务，避免把每次命中变待办。

每条问题展示对象ID/产品、问题类型、具体Claim/scope、风险因子、触发理由、候选摘要、Evidence数、创建时间/最后修改、当前处理状态。排序先实际已知利用且有授权资产影响，再关键字段冲突，余下按创建时间；无证据因子不编等级。按问题/对象/处理状态筛选，点击任务展开比较，列表位置保留。

## 对照与决定[R02/R03]

左侧当前发布观察和原人工结论；中间候选A/B，每条有生态/版本分支/日期/CVSS version、source/publisher/lineage和可点Evidence；右侧决定区域。先回答“是同scope吗”，不是先选谁可信。

| 操作 | 意义及必填 |
|---|---|
| 确认A / 确认B | 选具体候选Claim/value/scope及Evidence，填写理由；不删另一个观察 |
| 证据不足 | 当前不能作确定判断，记录缺口与需补证；保持unknown，不当“不受影响” |
| 暂不判断 | 未作事实决定，保存备注/原因，任务deferred可重新进入 |
| 补充备注 | 增加审计说明，不改变已确认值；不伪造外部证据 |

PoC任务只能确认关联依据；要标可用必须有独立授权隔离核验记录，界面本身不执行代码。人工不能仅凭同名repo确认Patch覆盖全部版本。正式结论写入前展示将改变的Claim/scope与原值/新值，明确确认按钮一次提交。

## 审计、并发与上游变化[R04/R05]

服务器写入记录actor（由会话确定，不能由客户端假填）、时间、对象/Claim、原结论、新结论、理由、Evidence IDs及版本、expected_revision、request/idempotency_key。提交后显示审计记录ID和最新revision，点“返回原漏洞字段”；只刷新相关Claim，不丢原Evidence。

409：他人/上游已经更新，保留本地草稿，展示当前候选变化，重新看Evidence后按新revision人工确认；不自动重发旧决定。提交超时：先查同请求决定是否落地，成功则显示记录，尚未完成显示处理中，确认未接受后才能重试同幂等键。网络失败绝不能显示“已确认”。

后续源修订不覆盖人工结论，而是产生新候选并标“新证据需复核”；用户对照新旧范围再作新决策，旧审计可回查。源撤销/证据失效同样提示，不能为了保留人工结论而隐藏更新。

## 状态与退出

Loading保留列表/原草稿；Empty表示当前无开放任务；No Result为过滤无匹配；Partial Data单个Evidence失败但其他可读；Stale Data显示候选日期，允许阅读旧版但提交需当前revision；Conflict作为具体问题而非整页错误；Evidence Insufficient可选择保留未知；Source Offline不取消现有任务。Error读/写区分恢复；无Review write显示只读对照、不能提交；Agent Timeout NA。取消编辑前有未保存备注则提示保留草稿/放弃/继续编辑，返回原Claim，不能困在审核页。

验收：同scope真矛盾有问题入口；跨scope先解释不生成假冲突；所有写决定留前后值/依据/actor；失败无假成功；409及新源修订均不静默覆盖。BACKEND REQUIRED：R01—R05，源及权限/API提案见依赖矩阵。
