# Conflict UI

冲突只表示同一对象/生态/包/版本分支/评估口径内的矛盾。跨CVSS版本、发布日期差异或不同scope用并列说明，不能每个差异都打冲突标签。

## 表达结构

1. 当前Claim旁“存在冲突”badge；页面局部低饱和莓色横幅，标题说明是哪一字段。
2. 两列Candidate A/B，同一字段排列：value、生态/包/分支、来源、时间、原文片段、Evidence入口。未知scope先写证据不足。
3. 原证据抽屉可读lineage/locator，冲突不删除任一观察；P1“进入对应复核”带Claim/review ID，不去空待办页。
4. Review选择确认A/B/证据不足/暂不判断，理由必填，预览原结论与新决定，人工确认后显示actor/time/value/reason/审计。原型仅在内存模拟，刷新恢复。

假设<0.8.4与<=0.8.5只用于交互设计。原型每处标“假设示例”；不存在真实供应商发现或准确率证明。NVD与CNA不同CVSS版本不当真实冲突，NVD仍是暂缓源。

## 并发与上游更新

409用局部说明“资料已更新，保留草稿”，展示当前revision与变化，再由人确认，不能静默重发。源新修订不覆盖既有人工决定，进入“新证据需复核”，保留前后值；已确认只是该Claim/scope，不扩成整条漏洞可信。

无权限只读，决定按钮不可执行；write结果不明先查幂等状态；SourceOffline可读已有证据；候选缺证允许保留unknown/暂缓，不强迫选A/B。红色只用于真正请求失败；Conflict不做全屏红报警。BACKEND REQUIRED V09/R01—R05/E04/A14—A16，P1不会因原型被提为P0。
