# 本阶段发现的UX澄清项

没有需要重构一级导航或五条核心流程的问题。Phase 3全部文件保持冻结，以下只是UI表达澄清及后续实现条件。

| 问题 / 输入 | 处理 | 是否修改冻结UX |
|---|---|---|
| UI任务示例“已确认POC”容易混淆 | 界面统一“已确认关联”，另列可用性未核验；不运行未知PoC | 否，遵循现有两轴 |
| 十列表格建议与Phase 3六组冲突 | 合并PoC/KEV/修复状态，长range/原文转详情；六组表格 | 否 |
| Prototype计数不是真实运行观察 | 标签改“本期示例集合”；指标/筛选数相符，生产再按first_observed/modified规范 | 否，原型示例不同于生产时间统计 |
| Source ID过于内部 | 用户见“vLLM公告/PyTorch公告”，内部ID在映射/定位展开 | 否 |
| 首版仅asset affected/unknown示例 | 加不受该漏洞影响的模拟版本样例，维持三态；新登记始终unknown | 否 |
| 人工Review回详情只显示原观察 | 单独显示人工决定层和值/理由/审计，原Observation不删除 | 否 |
| 原型包含P1可操作页面 | 全局mock及P1标记；生产按capabilities权限开放，不能当已实施 | 否 |
| 3—5分钟Demo建议包含资产与冲突 | 保留M2真实就绪路径及M1缩减路径，不构造真实冲突 | 否 |
| 真实响应、权限、并发和长列表缺少运行服务 | 以BACKEND REQUIRED交接，后续架构/联调验收 | 否，尚未进入数据库/后端阶段 |

页面步骤预算、30秒理解目标和Demo计时尚未做真实用户实验，不能因为原型看起来流畅就报告完成实际可用性验收。后续遇到真实数据导致的信息过载/流程断点再提出有依据的小修订，不在本轮大规模改UX。
