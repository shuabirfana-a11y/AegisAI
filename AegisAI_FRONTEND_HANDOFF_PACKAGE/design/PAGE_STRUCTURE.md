# 页面结构与数据入口

六个主导航、七个页面：情报总览、漏洞中心、资产风险、证据复核、智能调查、系统状态；漏洞详情从中心和相关对象进入。沿用真实 History 路由，不把 8768 原型的 hash 路由复制到 API 前端。

```text
AppShell
├── Navigation / 页面标题 / 权限与数据模式提示
├── /dashboard
├── /vulnerabilities
│   └── /vulnerabilities/{id}
├── /assets
├── /reviews
├── /assistant
└── /system
```

## 页面区块

| 页面 | 从上到下的结构 | 深入入口 |
|---|---|---|
| 总览 | 范围与时效 → 已有统计 → 重点漏洞/待复核 → 来源摘要 | 漏洞、资产、复核、系统 |
| 漏洞中心 | 搜索/筛选 → 表格 → 分页/查询范围 | 漏洞详情 |
| 漏洞详情 | 身份 → 影响版本 → 风险依据 → 修复 → Claim/Evidence → 冲突 → 时间线 | Evidence 抽屉、同范围调查、复核 |
| 资产风险 | 资产队列 → 组件/库存版本 → 风险快照 → 原因与建议 | 关联漏洞、历史快照、同资产调查 |
| 证据复核 | 队列 → Claim/作用范围 → 两侧证据 → 理由/决定预览 → 审计 | Claim 来源、原漏洞 |
| 智能调查 | 问题/范围 → 提交/恢复提示 → Stage → Agent/Task/Tool → Gate → Answer/引用 → 警告 | 引用抽屉、资产、漏洞、历史记录（待 API） |
| 系统状态 | health → source 状态 → sync-run 历史 → 错误摘要 | 同源同步记录 |

查看详情后返回，应恢复原列表查询、分页、滚动和来源上下文。资产 ID、CVE、组件版本不能靠自然语言猜测后偷偷改变。URL 参数应按服务端允许的筛选范围解析，避免把原型高级筛选全部当现有 HTTP 参数。

智能调查的新增状态视图是待前端实施需求，不表示已编码。真实旧问答与 Mock 完整调查使用独立适配器，结果组件可以复用但 DTO 不混用。

## 分层建议

在现有前端组织上增加薄数据适配：服务请求 → DTO 校验/状态收窄 → 页面 View Model → 展示组件。业务版本匹配、可信判定和风险评分留在后端。队友选择 React/Vue 时仍复用协议和页面结构，不先重写后端或为了目录名称迁移稳定模块。

已有项目位置说明：`frontend/public/modules/pages/` 是七页；`services.js` 是现有 API 包装；`state.js` 保存前端状态；`router.js` 管理页面路由；`frontend/server.mjs` 是本地代理。源码不包含在本交接包中，需要另行取得完整项目。
