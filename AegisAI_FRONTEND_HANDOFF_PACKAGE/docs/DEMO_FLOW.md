# 比赛演示流程

## 当前能诚实展示的两种演示

**真实现有接口演示**：漏洞中心 → 漏洞详情 → Claim/证据 → 有权限的资产风险快照 → 数据源/同步状态。旧问答可以额外展示，但属于旧协议。

**自主调查界面演示**：使用本包历史合成测试回执驱动 UI，明确展示“测试回执 / Mock”。Phase 11-D 后端有内部实现，当前浏览器 API 未开放；不能介绍为已完成的在线交互闭环。

不能用人工延时播放工具成功，或将 Mock 结果称为刚刚调用模型/抓取漏洞的结果。演示前检查实际联调环境能返回数据；此包没有检测线上可用性。

## 建议 5—7 分钟展示顺序

| 顺序 | 页面/内容 | 展示重点 | 数据模式 |
|---|---|---|---|
| 1 | 情报总览，约 30 秒 | 情报范围、当前数据源、资产指标的统计口径 | 现有 API；缺趋势不补造 |
| 2 | 漏洞中心 → 详情，约 1 分钟 | 版本、CVSS/CWE、来源与 Claim、PoC/补丁候选 | 现有 API，按实际可用数据选对象 |
| 3 | 资产风险，约 45 秒 | 所选组件与版本、影响/未知、快照时间 | 现有授权 API；用户库存不是主动扫描 |
| 4 | 智能调查结果，约 2 分钟 | 问题范围、Planner、调查 → 核验 → 分析 → Gate → Answer | 本包 PASS 场景，显式 Mock 标签 |
| 5 | 证据抽屉，约 45 秒 | Claim 关联、定位、哈希、支持/反对与来源 | 同一个 PASS 回执的投影 |
| 6 | 切换不足/复核场景，约 1 分钟 | 系统会拒绝强结论；COMPLETED 可以是不完整 | REPLAN_REQUIRED / HUMAN_REVIEW_REQUIRED |
| 7 | 系统状态，约 30 秒 | 已接入/计划源区别、失败与数据时效 | 现有 API，遥测缺失明确说明 |

第 4—6 步所用假 CVE、合成包名、example.invalid 来源都不是实际安全公告。建议在演示页顶部固定标注“历史代码执行 + 合成测试数据，非在线请求”。

## 展示可信性时说什么

- 调查发现是候选信息，证据核验是独立阶段；模型不是最终可信裁决者。
- 展示风险前同时展示影响范围、核验状态和处置依据。未知不表示安全。
- Integration Gate 有 PASS、带警告、需要再调查、需人工复核和失败，不能把通过条件只看成“几个任务都执行完”。
- AnswerEnvelope 使用冻结 Gate 上下文与确定性模板，引用回核验 Artifact，不靠答案措辞新增事实。
- 历史快照没有自动变成实时事实；资产登记是用户库存数据，不是扫描报告。

## Phase 12-B 之后才能验收的在线演示

提交新的调查 → 收到实际根 ID → 轮询状态 → 查看三个专业阶段与工具 → Gate → 读取 AnswerEnvelope → 引用定位；再演示相同 key 重试、取消中至取消终态、历史读取和恢复待确认。

目前这条在线流程仍待 API 实施、浏览器代理和鉴权适配。新契约未冻结前不要硬编码建议 URL。演示验收必须包括真实浏览器到后端的交互回执，不能只使用本包类型检查或历史“1261 项”记录。
