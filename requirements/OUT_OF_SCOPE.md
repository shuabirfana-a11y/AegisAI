# 当前不做与保留边界

全部排除为团队范围设计，不能写成比赛禁用技术清单。对应P3登记有验收/来源，安全限制另由P0保证。

| 排除 | 为什么 / 保留什么 | 需求 |
|---|---|---|
| 大型知识图谱平台 | 部署/建模成本高；必要关系、跨文档与Evidence仍做 | REQ-DATA-007 |
| Kubernetes/完整多租户企业IAM/大型分布式平台 | 初赛收益不匹配；最小权限、审计、自部署/容器工程仍做 | REQ-ENG-007 |
| 自动攻击、全网主动扫描、未知Exploit执行 | 不属于知识情报闭环；搜集与审阅PoC、授权隔离验证证据可输入，系统不自动运行 | REQ-SEC-007/003 |
| 自训练基础大模型 | 无题面要求，成本高；受限使用已有模型/Agent并评测 | REQ-AGENT-006 |
| 十几个无收益Agent | 不以数量换效果；少量协作P1、真实创新P2保留 | REQ-AGENT-005 |
| 复杂3D大屏 | 优先真实任务和证据，基本列表/图表可有 | REQ-UI-004 |
| 自动法律结论/企业合规平台 | 政策文本需来源/版本/语义检索；不自动判断某组织违法 | REQ-MON-002的团队边界 |
| 从所有情报直接生成可信结论/伪造成绩 | unknown、人工例外与错误透明；没有验证就不称可用PoC/修复/命中/准确率 | REQ-VERIFY-003、REQ-EVAL-001 |

**不排除**：论文、技术标准、政策法规知识同步；它们是原文明示。**不省略**：自然语言跨文档问答与实际Agent，属于完整P0交付。Dify品牌、框架/数据库型号和七个页面不是题面指定，后续技术/产品阶段再决定。

当前需求阶段还禁止继续做：新数据采集/源接入、数据库设计、UX/UI、前后端、Dify或Agent实现。这是用户给本阶段的工作边界，不是最终产品取消这些能力。完成13份需求文档即停止。


需求属性与来源的完整登记以 [FEATURE_LIST.md](FEATURE_LIST.md) / [requirements.json](requirements.json) 为准；具体实现尚未开始。
