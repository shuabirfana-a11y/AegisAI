# 非功能需求

所有目标是未来验收条件，当前没有性能或部署完成结果。官方门槛和内部细化分开。

| 方面 | 官方依据 / 团队细化 | 验收与需求ID |
|---|---|---|
| 性能 | 官方采集24/12/6h与决赛答复≤5s；团队记录完整答复、逐条时延、P50/P95、硬件/并发/缓存/超时 | REQ-MON-004、REQ-EVAL-003/006；缺时间与失败单列，不能只给平均值 |
| 可靠性 | 官方异常处理/稳定性；团队设置隔离、预算、回补、状态和恢复 | REQ-ENG-002；单源故障不拖其他任务，DB全故障不得伪装成功，恢复重复同步不产生重复事实 |
| 可追溯 | 团队设计支持官方准确率；重要断言有Claim、原文定位、Hash、发布者和时效 | REQ-VERIFY-001/002；点击任一重要结论回查实际证据，转载链明示 |
| 安全 | 团队与用户要求；PDF另规定代码审阅防泄露与决赛PPT匿名 | REQ-SEC-001—006；外部prompt不授权、未知代码不运行、secret无泄漏、授权资产与最小权限、匿名检查 |
| 可维护 | 团队设计；职责边界、来源parser/schema版本、可复现工程测试和文档 | REQ-ENG-003/004、REQ-EVAL-001；更新一个来源能定位变化与回归，不改全部业务 |
| 可扩展 | 官方Agent可扩展/创新评分；团队以有版本业务契约新增源/生态/工具 | REQ-AGENT-004；新增能力能复用证据/权限，不预建大型平台 |
| 可观测 | 团队设计支持官方自动化；任务状态、成功/失败/重试、coverage、stale、工具结果 | REQ-MON-005、REQ-ENG-002；真实记录和安全日志能解释失败与用户看到的缺口 |
| 可部署/可恢复 | 官方学生自部署与决赛工程；团队提供环境/配置/启动/备份恢复验证 | REQ-ENG-003/004；在声明环境复现，不依赖未承诺资源 |
| 数据真实性 | 团队可信边界；未知不伪装确定、撤销传播、状态不被问答改变 | REQ-DATA-002、REQ-VERIFY-003；候选与已确认分开，原始观察留存 |

性能实验必须说明业务范围与样本分母。P0要求采集与Agent正常闭环可运行；更高24→12→6h、准确率和工程评分档以测量结果证明，不预先保证成绩。真实API/外部模型不可用时保留已知数据和可解释错误，Demo回放需明确标注。


需求属性与来源的完整登记以 [FEATURE_LIST.md](FEATURE_LIST.md) / [requirements.json](requirements.json) 为准；具体实现尚未开始。
