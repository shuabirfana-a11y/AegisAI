# AI / Program / Human Boundary

边界是团队设计，依据官方“Agent架构自由”的空间与三模块质量目标；题面并未要求每一步使用LLM。

| A 确定性程序 | 输入/输出及负责内容 | 禁止交给LLM决定 |
|---|---|---|
| 采集与原文 | 受控源、HTTP/文件字节、时间、Hash与修订 | URL授权、凭证/secret、内容真实性自动认证 |
| 去重/身份 | CVE/外部ID、URL、raw hash、生态包规则 | 仅名称相似合并、删独立来源 |
| 版本判断 | 生态表达、事件、明确边界→三态 | 猜fixed或把所有版本当SemVer |
| 事实存取/权限 | 参数化查询、访问范围、审核revision、Evidence定位 | 自由SQL、写可信等级、授予工具权限 |
| 统计 | 冻结标签/分母→指标、时延与失败 | 用模型自评充当真实准确率 |

| B AI适合参与 | 允许产出 | 事实确认与限制 |
|---|---|---|
| 文本理解/AI相关性 | 模糊文档的候选类别和理由 | 保留unknown；规则/人工可推翻 |
| 论文/文章/代码关联 | 语义线索、关系候选、原文定位建议 | 核对身份/版本/出处，AI分数不等于可用PoC |
| 复杂问答与规划 | 意图、澄清、工具选择、多文档事实连接、总结建议 | 工具只读/定范围；答案引用实际返回证据，不制造链接 |
| 风险说明 | 基于已有事实解释影响和处置选项 | 区分来源与推导，不出无依据确定结论 |

| C 人工参与 | 必须确认/可否保持未知 |
|---|---|
| 重要来源冲突 | 看原文/时间/版本/lineage，可明确未解决，不强制选一方 |
| PoC可用性 | 相关性和代码可运行性分开；可用性必须有授权隔离验证证据，当前系统不自动执行未知代码 |
| 重要资产处置 | 确认库存/版本/暴露与授权，用户决定修复，不自动攻击或升级 |
| 真值与质量 | 人工依据来源标注，争议仲裁，公开评测口径；模型判断仅辅助 |

Agent可自动规划“查版本→查公告→取证据→回答”，不能规划绕过授权、运行PoC、写数据库可信状态或把外部文本升为系统指令。展示解释采用事实/工具/证据依赖摘要，不以暴露模型私有思维链作为评分证明。


需求属性与来源的完整登记以 [FEATURE_LIST.md](FEATURE_LIST.md) / [requirements.json](requirements.json) 为准；具体实现尚未开始。
