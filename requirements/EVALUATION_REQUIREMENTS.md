# Benchmark与评测需求

本阶段只冻结怎么测，不采集新数据、不标注虚构gold、不执行模型/PoC/服务。官方分档见SCORE_MAPPING；下面的集合划分、指标定义和实验细节是团队可操作口径。评审另有细化时按版本更新，不静默改分母。

## 1 数据与真值

人工从原始公告、版本/修复说明、论文及授权资产确定标签，保存as_of、原文定位、判断人/理由；有争议单独仲裁或标UNKNOWN。PoC“与漏洞相关”与“可用性已验证”两类真值分开。Patch必须有适用分支/版本证据。源镜像、同GHSA/同repo相近修订按主体/lineage分组拆分，避免测试泄漏。

开发/验证/最终测试分离；测试集冻结hash，不用最终测试结果反复调提示词。明确来源/产品/时间/类型分布及代表性限制。现有12条6产品机器核验候选只作后续开发输入，仍待人工逐项审阅，不支持已达准确率或全域召回的结论。测量样本不足或分母为0报告N/A，不写100%。

首次规模由可获得真值决定，至少要有正例、真实负例、易混淆、缺失、unsupported、撤销与跨文档任务；本阶段不把任何建议样本数写成已完成事实或官方规定。

## 2 指标与分母

| 指标 | 怎么测 / 分母 | 官方还是团队 |
|---|---|---|
| AI相关性 Precision/Recall/F1 | TP/(TP+FP)、TP/(TP+FN)、2PR/(P+R)；明确AI/非AI人工真值，UNKNOWN单列并报告coverage；不通过移除难例抬分 | 团队专项，非官方独立指标 |
| 版本Accuracy | 人工/生态规则真值的受影响/不受影响/UNKNOWN；明确集合总体正确数/N；同时给已支持范围正确率及coverage、边界子类 | 团队专项支持富化/问答 |
| POC关联Precision/Recall | 正确已输出关联/全部已输出关联；命中的已知正确关联/完整标注正例集合；可用性单独测试，候选不算verified_usable | 团队专项支持富化 |
| Patch关联Precision/Recall | 完整SHA、适用分支/版本与修复依据判定；错误关联为FP，漏掉完整真值为FN | 团队专项支持富化 |
| 富化Accuracy | 操作定义为正确且相关的已输出事实/关联数÷全部已输出事实/关联数；每维度及宏/微统计都报告，冲突/unknown/候选分开 | 官方准确率，团队定义可重复操作分母；不是全局TN混入准确率 |
| 富化Recall | 检出的正确事实/关联÷该冻结源/时间/产品范围内已穷尽人工正例；若真值未穷尽，不报告覆盖全域的召回率 | 决赛官方召回；团队限定可知范围 |
| 基础问答Accuracy | 逐题rubric：2完整正确/引用适用，1部分正确，0错误/无依据；Accuracy=2分题数/全部测试题，另报部分分；超时/失败不排除 | 官方准确率，团队判题规则 |
| 多跳问答Accuracy | 题目确需至少两个事实连接/跨文档；看答案、实际工具/证据依赖、日期/版本scope，按同rubric算；不得展示模型私有思维作为证据 | 官方多跳/推理能力，团队任务定义 |
| 引用有效性 | 原文确支持对应断言且定位存在的引用÷全部给出的关键引用，漏引断言另统计 | 团队问答专项 |
| Correct Abstention Rate | 应拒答/澄清样本中正确说明未知的比例；已知可答集合误拒率另报；部分可答不应全部拒绝 | 团队专项 |
| 响应时间P50/P95 | 请求开始至完整答复结束；网络、模型、检索均计入；逐题完整时延、失败/timeout与并发/缓存配置报告 | 官方决赛≤5s；P50/P95为团队补充，不用首token代替 |
| 采集Latency | 首次有效获取−源首次发布；新增前瞻集合统计，历史回补独立；时间未知/负时钟/发布源延迟/未采集单列并报告覆盖 | 官方时效，团队操作定义 |
| Agent任务成功/工具效率 | 目标是否完成、工具选择/实际调用次数、错误恢复、延迟和成本；单/协作相同任务预算对比 | 官方Agent能力，团队度量 |

正确拒答可在专门的不可回答任务rubric中判正确，普通可回答问题不能靠拒答拿满分。原文“准确率”没有完整公式，当前口径显式披露；评审要求其他公式时保留本口径结果并追加重算。

## 3 官方阈值（只作未来门槛）

- 初赛：时效≤24/12/6h；富化准确率≥70/85/95%；基础QA≥70%，优秀档多跳≥85%；深度问答含推理链是良好描述档而非另一个虚构百分比。
- 决赛：时效≤24/12/6h；富化准确率/召回≥80%/70%、90%/90%、95%/95%；QA准确率≥75%且响应≤5s为合格，≥90%且多跳为良好，≥95%且推理链可解释为优秀。
- 工程/功能分档同时需要实际功能：源类别3/5/7、富化维度3/5、实际Agent、自动化与工程、规定材料。单个漂亮百分比不能替代完整功能。

QA≤5s按完整响应逐题记录和达标率呈现；内部可采用全部成功题≤5s的严格验收，不能因P95≤5s就称全部门槛满足。题面未规定聚合口径，要注明而不是补成官方P95阈值。对复杂多跳单独披露耗时与失败。

## 4 工程验证与对照

Unit：版本边界/别名/规范化/unknown；集成：去重、修订、Evidence和撤销、持久化失败；API/前端：权限、空/错误/分页、引用回查；运行：源故障、重试预算/回补、备份恢复；Agent：越权/外部提示注入、工具错误、不支持问题。日常使用离线fixture，少量真实接口测试显式运行，避免测试完全依赖互联网。

对照按同集合/同预算：单源→多源（先去转载重复）、无核验→有证据核验、单Agent→少量协作、关键词→语义/跨文档。输出实际结果、置信区间或样本不确定性、成本与失败例。人工可复核，不将LLM judge单独当gold。

结果记录必含需求ID/评分点、dataset revision、as_of、配置/模型/环境、样本数/分母、失败和unknown、逐条结果及汇总。每次声称提升均可回放；本阶段不生成任何成绩数值。
