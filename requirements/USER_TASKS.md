# 用户任务与成功条件

任务是产品设计；示例问题不能替代真实检索/授权资产。先任务，再页面。

| ID | 用户 | 要完成什么 | 必要输入 | 成功结果 | 对应需求 |
|---|---|---|---|---|---|
| TASK-01 | R1 | 发现本期新增/变更的AI安全情报 | 源类别与时间、候选列表 | 查到真实记录、来源和首次获取时间 | REQ-MON-001/003/004/005；REQ-UI-001 |
| TASK-02 | R1/R2 | 判断漏洞影响产品和版本 | 产品/包/版本、源范围 | affected/not_affected/unknown与依据 | REQ-DATA-003/004；REQ-ENRICH-005 |
| TASK-03 | R1 | 判断GitHub代码是否相关PoC及可用性是否证实 | CVE、repo、版本、公告、代码线索 | 相关性和可用性分开，候选不会变已验证 | REQ-ENRICH-004；REQ-VERIFY-001/003 |
| TASK-04 | R1 | 查看风险结论为什么成立 | 来源评分、利用信号、影响/版本、日期 | 可回查事实和推导，不以来源数投票 | REQ-ENRICH-002；REQ-VERIFY-001/002 |
| TASK-05 | R2 | 判断自己的组件及授权暴露资产是否受影响 | 授权库存/版本/环境 | 匹配结果、缺口和修复依据 | REQ-ASSET-001/002；REQ-SEC-004 |
| TASK-06 | R1/R2 | 问最近90天影响指定推理组件且有已核验PoC的高危漏洞 | 明确as_of、时间范围、组件、PoC状态 | 实际多步查询；没有结果诚实返回空/未知 | REQ-QA-001/003/004；REQ-AGENT-002 |
| TASK-07 | R1 | 处理同范围来源分歧 | 双方原文、时间、版本、lineage | 记录确认/未解决与理由，保留原Evidence | REQ-VERIFY-004/005；REQ-SEC-005 |
| TASK-08 | R1 | 查看最新论文、标准和政策及其出处 | 文档类型、日期/版本、关联候选 | 可阅读并定位原文，不把政策文本当自动法律判断 | REQ-MON-002；REQ-ENRICH-003；REQ-UI-001 |
| TASK-09 | R1 | 追踪旧情报修订、撤销和修复变化 | 稳定身份、历史观察 | 知道何时/谁/依据什么变化，旧结论状态明确 | REQ-DATA-002/006；REQ-VERIFY-001 |
| TASK-10 | R2 | 发现并恢复一个源任务故障 | 运行状态、失败类型、回补记录 | 其他任务继续，恢复后回补不重复 | REQ-ENG-001/002/005；REQ-MON-005 |
| TASK-11 | R1/R2 | 证明系统能力、质量与实际交付 | 评测真值、结果、Demo、提交物 | 结果可重现且与功能一致，所有评分点有证明入口 | REQ-EVAL-001/002/003/006；REQ-ENG-006 |

复杂问题必须确认as_of、产品/包/版本、日期口径和“PoC已核验”的定义；缺任何关键输入先澄清。用户没有授权资产时可分析公开组件信息，不能假定真实环境受影响。历史案例不冒充90天新增。


需求属性与来源的完整登记以 [FEATURE_LIST.md](FEATURE_LIST.md) / [requirements.json](requirements.json) 为准；具体实现尚未开始。
