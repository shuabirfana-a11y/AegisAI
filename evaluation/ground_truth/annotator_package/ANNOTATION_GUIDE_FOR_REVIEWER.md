# 人工标注与独立复核：人员说明

这份说明供标注人、复核人和负责人先统一理解。具体操作见[标注手册](ANNOTATOR_TASK_MANUAL.md)和[复核手册](REVIEWER_TASK_MANUAL.md)。

## 人工标注到底是什么

不是对系统回答点“好”或“不好”，而是先不看系统答案，自己查原始资料，写出一份可以作为评分依据的答案。

一条合格记录应说明：问题问了什么、输入条件是什么、结论是什么、哪段资料支持它、哪些条件还不明确。表单中的 `expected_answer` 是标准答案；`judgments` 把答案拆成可以逐项检查的判断；`evidence` 保存原文与来源。

## 独立复核是什么意思

复核人不是只检查有没有漏填，也不是代替标注人复制答案。复核人需要自己打开原始公告或冻结资料，核对原文、版本范围和引用关系，再判断答案是否成立。

不必从头另写一整份答案，但必须有自己的查源和判断过程。例如，标注人声称某个版本受影响，复核人要检查原公告的包名、分支和区间边界，不能因为答案写得完整就批准。

同一人换两个账号、AI 使用两个人名、两人一起看 AI 答案后直接同意，都不满足独立复核。

## 建议的最小分工

| 角色 | 实际工作 | 不能替代的环节 |
|---|---|---|
| 标注人 | 阅读问题、亲自查源、填写结论和证据、处理退回 | 不能用 AI 输出代替原始来源 |
| 独立复核人 | 亲自查源、检查完整答案、记录分歧、批准或退回 | 不能复核自己的标注 |
| 数据管理员 | 分配任务、核对字段和哈希、保存修订、同步台账、提交 PR | 格式通过不能替代人工证据判断 |

管理员可以由其中一位成员兼任，但同一道题仍需两位不同真人完成标注和复核。两个人可以在不同题目上互换角色，每题的两人身份都要独立留痕。

团队 ID 可以匿名，负责人应保存 ID 与实际人员的对应关系。不要在公开材料中填写手机号、账号密码、API Key 或真实资产秘密。

## 人员暂时没确定怎么办

保持任务未分配、人工记录未开始。可以先阅读说明和候选资料，但不能预填标注人、复核人、审核时间或批准记录。

目前 49 题中人工填写、独立复核和批准均为 0；第一批 10 题只有任务和资料准备。确定人选以后，再由管理员登记真实分配。

## AI 可以帮到哪一步

可以帮助查找资料入口、整理候选引用、翻译辅助阅读、检查格式。成员必须亲自核对引用的原文，并在 `ai_assistance` 中如实说明辅助用途、工具版本、实际时间和人工查源范围。

AI 不能充当标注人、复核人或最后裁决者。AI 找到了来源也不能自动把该来源标成“已支持答案”。

## 分歧与不确定怎么处理

先定位分歧：是包名不同、分支不同、公告更新、版本条件缺失，还是原文并不支持结论。把分歧及两方证据写下来，继续查源。

没有可靠结论时可保留 `UNKNOWN` 或 `INSUFFICIENT_EVIDENCE`。如果两人对标注记录是否合格仍有实质分歧，由第三位真实成员复查；没有第三人时保持待复核或按理由退回，不自动批准。

## 什么才算复核完成

复核人已读完整答案与原始证据，逐项填写检查表、意见和实际时间，确认审核绑定的是当前内容哈希。管理员再核对修订和真实人员记录。

`APPROVED` 表示这份人工记录符合规范；它可以包含有依据的未知结论，不表示每个漏洞、补丁或利用都被确认。导出与正式评测是后续工作，本次文档任务不执行。
